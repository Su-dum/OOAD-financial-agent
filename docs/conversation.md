# 交互式分析：自然语言追问与条件修改（C2 / C1）

> 评分原文两条：
> - *Support natural-language follow-up questions and allow users to modify analysis or
>   monitoring conditions interactively.*
> - *Provide a user-friendly interface for users to configure monitoring targets, analysis tasks,
>   and alert conditions.*

## 一、两类能力，一个入口

`POST /api/chat` 同时处理「问」和「改」：

| 用户说 | 意图 | 处理 |
|---|---|---|
| 「这只票最近表现怎么样？」 | `performance` | 取区间指标，模板/LLM 作答 |
| 「为什么 8 月 15 日放量？」 | `reason` | 取事件 + 公告 + 新闻，明确区分「同期」与「因果」 |
| 「有哪些财报或回购公告？」 | `notice` | 取重大类公告并按类别归集 |
| 「和 000001 比较一下」 | `compare` | 触发 D3 跨资产计算，把对比结果作为证据 |
| 「把跌幅阈值改成 3%」 | 条件修改 | 解析成 `set_alert` 动作 -> **服务端落库** |
| 「看近半年」 | 条件修改 | 解析成 `set_range` 动作 -> **前端切区间** |
| 「把 601318 加入自选」 | 条件修改 | 解析成 `add_watchlist` 动作 -> **服务端执行** |

设计原则：**「改条件」不是聊天，是意图到结构化动作的映射**。
动作由服务端或前端执行，自然语言与表单走同一套配置服务，行为不会两套漂移。

## 二、意图路由（确定性，不靠模型）

```python
_INTENTS = (
    ("reason",      ("为什么", "原因", "成因", "怎么回事", ...)),
    ("compare",     ("比较", "对比", "相关", "联动", "跑赢", ...)),
    ("notice",      ("公告", "财报", "业绩", "分红", "回购", "减持", ...)),
    ("events",      ("事件", "异动", "放量", "异常", ...)),
    ("news",        ("新闻", "消息", "报道", ...)),
    ("performance", ("收益", "涨", "跌", "表现", "回撤", "夏普", ...)),
)
```

先匹配到的赢，都没有则 `overview`。为什么不用 LLM 做意图分类：

- 确定性路由**没有 LLM 也能跑**（断网/网关 503 时功能不缺失）；
- 路由结果决定走哪条取数路径，让模型决定会引入不可预测的延迟与费用；
- 关键词表一目了然，答辩时能解释「为什么这句被理解成 compare」。

## 三、证据编号 + 引用校验（与调查报告同一套规则）

一次追问会把本地数据整理成**编号证据**：

```
[1] (indicator/计算(baostock)) 区间行情与指标 —— 累计收益 +2.90% …
[2] (event/规则(notice_event)) 2026-10-31 notice_earnings —— 财报披露：…
[3] (cross/跨资产计算) 相对表现与相关性 —— 区间内相对表现：…
[4] (notice/巨潮/东财公告) [财报披露] 2026年第三季度报告
[5] (news/财联社) ……
```

LLM 的回答必须满足：

1. `answer` 非空；
2. `cited_evidence_ids` 里的每个编号都真实存在（越界即判幻觉）；
3. 有证据却一个都不引用，且没有声明 `insufficient_evidence` -> 判无据。

任一条不满足：**整段丢弃，退回模板答案**，并在响应里标 `llm_meta.degraded=true` + 真实原因。
模板答案自己也会带 `[1][2]` 编号，所以「降级」不影响可追溯性。

> 实测：2026-11-17 网关连续返回 `HTTP 503 Service temporarily unavailable`，
> 两次退避重试 + 备用模型仍失败 -> `llm_meta.reason` 记录原始异常，前端显示「LLM 降级」徽标，
> 答案仍完整（模板），功能不崩。

## 四、模板答案也要能干活

没有 LLM 时按意图拼装：

- `performance`：区间收益 / 年化波动 / 最大回撤 / 夏普 / PE，带 `[1]`；
- `reason`：列出最早/最近事件与公告，并**明确说「同期不代表因果」**；
- `notice`：把重大类公告按类别归集（财报披露、分红派息、股份回购…）；
- `compare`：给出各标的区间收益与基准同期表现；
- 没有任何数据：直说「该区间没有取到行情/公告，建议先更新数据」。

## 五、条件修改的三道闸

1. **解析保守**：只有出现明确数字/单位才动作
   （`把跌幅阈值改成 3%`、`看近半年`、`把 601318 加入自选`）。
   `近半年` = 183 天，不是 6 年——这里踩过坑，单测锁住了。
2. **参数校验在服务端**：`AlertConfigService.update()` 对每个参数有上下界，
   越界**拒绝**而不是静默钳制（避免「用户以为改了、其实没改」）。
3. **执行结果可见**：响应里 `applied` 数组逐条给出「已执行 / 未执行 + 原因」，
   `set_range` 由前端执行后提示「上方图表会按新区间重算」。

## 六、预警条件配置（C1）

### 三级合并

```
出厂默认（代码里的 DEFAULT_RULES）
   └─ 全局配置（alert_rule.code = ''）
        └─ 个股覆盖（alert_rule.code = '600519'）
```

改一只票不会影响其它票；想改全体就把 `code` 传空。前端展示的始终是**合并后的生效值**，
并标注来源（出厂默认 / 全局配置 / 个股覆盖）。

### 可配参数与边界

| 规则类型 | 参数 | 边界 | 含义 |
|---|---|---|---|
| `threshold_pct_change` | `drop` | [−0.30, −0.005] | 单日跌幅阈值（负数） |
| | `surge` | [0.005, 0.30] | 单日涨幅阈值 |
| `volume_spike` | `window` | [5, 120] | 均量窗口（交易日） |
| | `multiple` | [1.2, 10] | 放量倍数 |
| `zscore` | `window` | [20, 250] | 统计窗口 |
| | `z` | [1.5, 6.0] | 异常阈值（标准差） |
| `notice_event` | `min_severity` | low/medium/high | 公告事件最小级别 |
| | `include` / `exclude` | 类别 key 数组 | 只看/排除某几类公告 |

百分比在**界面层**换算（界面填 `3`，提交 `0.03`），领域模型里始终是小数，只有一套口径。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/alerts?code=600519` | 生效配置（含来源与边界） |
| PUT | `/api/alerts` | 改参数（`code` 空 = 全局） |
| DELETE | `/api/alerts/{rule_type}?code=` | 删除覆盖值，退回默认 |
| GET | `/api/chat/suggestions` | 追问示例（前端快捷按钮） |

## 七、实测样例

```bash
curl -s -X POST http://127.0.0.1:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"question":"把跌幅阈值改成 3%","code":"600519"}' | jq '{intent, actions, applied, answer}'
```

```jsonc
{
  "intent": "performance",
  "actions": [{"type": "set_alert", "rule_type": "threshold_pct_change",
               "params": {"drop": -0.03}, "describe": "把跌幅阈值改为 3.0%"}],
  "applied": [{"ok": true, "effective": {"drop": -0.03, "surge": 0.05}}],
  "answer": "已调整：把跌幅阈值改为 3.0%（规则已生效）。…"
}
```

## 八、已知限制

1. **追问是单轮上下文**：历史只带最近 6 轮（前端传），服务端无会话状态。
2. **不支持自由 SQL / 任意计算**：只回答有本地数据支撑的问题；
   问「十年后股价」这类问题会得到「证据不足」而不是编造。
3. **`set_range` 只影响本页**：不改配置、不落库。
4. **LLM 降级时答案较模板化**：模板只覆盖 6 类意图；复杂追问会得到通用概览。
5. **意图关键词是中英混排的**：纯英文提问会落到 `overview`，目前界面以中文为主。
