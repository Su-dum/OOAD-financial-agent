# 数据生命周期与「一键更新」

> 解决两个问题：
> ① 新闻日积月累会让数据库无限膨胀；
> ② 用户不该为了看事件列表去手动跑命令行。

## 一、为什么要设保留期

实测增长速度：

| 指标 | 实测 |
|---|---|
| 新闻增速 | **约 300 条/天**（50 天累积 15,058 条） |
| 单条占用 | 约 2,845 字节（含 trigram 全文索引，占 67%） |
| 50 天后的库 | **41 MB** |
| 不设限，1 年后 | ≈ 11 万条 / **300 MB+** |

而这 11 万条里，**对「事件调查」真正有用的只有最近几十天**——调查窗口通常 7~30 天。
再往前的新闻几乎不会进入推理，只是占着磁盘和索引重建时间。

## 二、分档保留策略

| 数据 | 默认保留 | 理由 |
|---|---|---|
| `news` | **90 天** | 事件调查主要看近期；更早的新闻基本不参与推理 |
| `event` | **180 天** | 行很小（~200 字节），留久一点便于回看历史异动 |
| `report` | **永久** | 是最终交付物，且数量极少 |

可用环境变量覆盖：

```ini
NEWS_RETENTION_DAYS=90
EVENT_RETENTION_DAYS=180
```

### 为什么是「删除」而不是「归档」

这些数据**都能重新拉回来**：东财新闻列表可回溯 200 天、财联社 180 天。
归档成 parquet 只增加复杂度，不增加能力。真要做长期存档再加一层。

### 删除时要注意的三件事（都已处理）

1. **`news_stock` 级联删除** —— 靠外键 `ON DELETE CASCADE`（连接已开 `PRAGMA foreign_keys=ON`）
2. **全文索引同步** —— `news_fts` 由 `news_fts_ad` 删除触发器维护，不会留孤儿
3. **回收磁盘** —— 大批删除后执行 `VACUUM`（41 MB 量级约 1 秒）
4. **安全阀** —— 单次删除超过 `max_delete`（默认 20 万行）直接拒绝执行，
   防止把 `NEWS_RETENTION_DAYS` 误写成 0 把库删空

## 三、一键更新：四步、限时限量

前端那个「更新数据」按钮调用 `POST /api/refresh`，一次完成：

```
① 新闻增量补齐（东财翻页，只补最近 N 天，页数上限 12）
② 实时快照（东财快讯 200 条 + 财联社电报 20 条）
③ 自选股事件检测 → 落库（前端事件列表直接读它）
④ 按保留策略裁剪旧数据
```

### 为什么每一步都有上限

这是个**同步 HTTP 请求**，必须在用户可接受的时间内返回，所以：

| 上限 | 默认 | 原因 |
|---|---|---|
| `news_days` | 2 天 | 只补最近缺口，历史一次性补齐另用 CLI |
| `max_pages` | 12 页 | 每页约 0.8 秒，12 页约 10 秒 |
| `stop_on_known` | 连续 6 页全重复即停 | 已采过就快速结束 |
| `detect_days` | **90 天** | 必须 ≥ 61 个交易日，否则 z-score 规则无法工作 |

> `detect_days` 这个坑踩过：一开始设 45 天，结果自选股事件始终是 0 个——
> `ZScoreRule` 需要 61 个历史点算基准，窗口不够就直接跳过。
> 改成 90 天（约 62 个交易日）后正常。

### 监控场景优先用快源

事件检测要拉价格序列。`baostock` 实测可能 60 秒+，所以刷新时**指定 `source="sina"`**
（约 2 秒/只）。新浪的前复权口径已验证正确（偏差 6.95e-06），不影响检测结论。

## 四、自选股（Watchlist）

对应提案 4.4 里原本缺失的 `Watchlist` / `MonitoringTask`。

```
domain/watchlist.py         WatchItem（值对象）+ Watchlist（聚合根）
infrastructure/repositories/watchlist_repository.py   SQLite 实现
```

- 表为空时自动预置 6 只常见标的，避免界面空白
- 支持加/删、去重（带 `.SH` 后缀也能识别）、批量导入
- 刷新只扫自选股，不做全市场检测（5,229 只逐只拉行情不现实）

## 五、接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/refresh` | 一键更新（新闻+快照+事件+清理） |
| GET | `/api/watchlist` | 自选股列表 |
| POST | `/api/watchlist` | 加入自选 |
| DELETE | `/api/watchlist/{code}` | 移出自选 |
| GET | `/api/events/watchlist` | 自选股已落库事件 |
| GET | `/api/maintenance/stats` | 数据量与保留策略现状 |
| POST | `/api/maintenance/prune` | 手动裁剪（支持 `dry_run`） |

## 七、前端交互

```
┌─ [更新数据] ── 新增新闻 13 条 · 扫描 6 只 · 检测事件 7 个 · 清理 0 条 · 耗时 8.0s
│
├─ 自选股事件  [6 只自选]
│   贵州茅台 ×  平安银行 ×  宁德时代 ×  中国平安 ×  比亚迪 ×  紫金矿业 ×
│   2026-10-23  宁德时代  上涨异动  medium   单日上涨 7.80%…      [调查]
│   2026-10-21  宁德时代  下跌异动  high     单日下跌 -12.03%…    [调查]
│   …
│
└─ 个股分析  [输入代码]
```

- 点自选股 chip → 查看该股指标
- 点事件「调查」→ 生成带引用编号的报告，页面自动滚到报告处
- 点 chip 上的 `×` → 移出自选

## 八、已知限制

| 限制 | 说明 |
|---|---|
| 刷新是同步请求 | 约 8~20 秒，期间按钮显示「更新中」。真要后台跑得加任务队列 |
| 只检测自选股 | 全市场 5,229 只逐只拉行情不现实；需要时可分批扩容 |
| 保留期内不归档 | 超期直接删，靠 backfill 可重新拉回 |
| VACUUM 会锁库 | 只在真正删了数据时执行，且耗时很短；并发写入时可能等待 |
