# 金融指标计算

> 对应评分项 **A2（计算金融指标）** 与 **A3（历史分析与比较）**。
> 「金融计算正确性」是评分维度之一，所以每个指标都有**可复算的验证方式**。

## 一、为什么单独成层

提案 4.3 明确写了：

> 金融指标计算和明确的阈值判断将优先由确定性的程序逻辑完成。大语言模型主要负责协调
> 工具调用、整合检索信息和生成解释，**而不是替代程序执行数值计算**。

所以 `backend/app/core/indicators.py` 是**纯函数模块**——不碰网络、不碰数据库、不碰 LLM。
输入一条价格序列，输出一组数字，可以单元测试。

## 二、口径前提（最重要的一条）

**所有指标都基于同一条前复权序列，且这条序列必须来自 baostock。**

原因见 [`datasource-eval.md`](datasource-eval.md) §7：东财的 `adjust="qfq"` 收盘价在非除权日
不满足「复权收益 == 不复权收益」这个恒等式（675 天里 470 天不符），直接拿它算收益率会
让年化波动率虚高 1.23pp。

因此 `PriceRecord` 上**显式记录了 `adjust` 和 `source`**，`PriceSeries.source` 会一路带到
`IndicatorSet`。报告里必须标注口径，否则「金融计算正确性」无法自证。

## 三、公式

设收盘价序列 $P_0, \dots, P_n$（前复权），$n$ 为交易日数减 1，年化按 252 个交易日。

| 指标 | 公式 | 说明 |
|---|---|---|
| 日收益率 | $r_t = P_t / P_{t-1} - 1$ | 前一日为 0 时按 0 处理，不除零 |
| 累计收益 | $P_n / P_0 - 1$ | 含首日到末日 |
| 年化收益 | $(P_n / P_0)^{252/n} - 1$ | **几何**年化，用交易日数而非自然日 |
| 年化波动率 | $\sigma(r) \times \sqrt{252}$ | $\sigma$ 为**样本**标准差（ddof=1） |
| 最大回撤 | $\min_t \left( P_t / \max_{s \le t} P_s - 1 \right)$ | 同时返回峰值日与谷值日 |
| 下行波动率 | $\sqrt{\frac{1}{n-1}\sum \min(0, r_t - mar)^2} \times \sqrt{252}$ | 只统计低于目标的收益 |
| 夏普比率 | $\dfrac{\bar r - r_f/252}{\sigma(r)} \times \sqrt{252}$ | $r_f$ 为**年化**无风险利率，默认 0 |
| 索提诺比率 | 同上，分母换下行波动率 | 对上涨波动不惩罚 |
| 胜率 | $r_t > 0$ 的天数占比 | |
| 估值分位 | 区间内 $\le$ 当前值的样本占比 | 0.2 表示处于历史低位 20% |

估值与成长字段：

| 字段 | 来源 |
|---|---|
| `pe_ttm` / `pb` / `ps_ttm` / `pcf_ttm` | baostock 日频行情**同一次请求**带回 |
| `pe_ttm_percentile` / `pb_percentile` | 用区间内自身序列算分位 |
| `roe` / `profit_growth` / `revenue_growth` / `market_cap` | 申万映射表快照 `data/seed/sw_stock_map.csv` |

## 四、怎么验证算得对

金融指标算错是**静默错误**——程序不报错，只是数字不对。所以做了三重验证：

### 4.1 单元测试（离线，19 个）

```bash
python -m pytest tests/test_indicators.py -q
# 19 passed
```

关键用例：

- **可手算的定值**：252 个交易日翻倍 → 年化收益正好 +100%；126 个交易日涨 20% → 年化 44%
- **零波动边界**：每日恒定 +1% → 年化波动率必须为 0；恒定收益 → 夏普返回 `None` 而不是除零
- **单调序列**：单调上涨的最大回撤为 0；`[100, 80, 60]` 的回撤为 −40%
- **随机序列与 O(n²) 暴力实现比对**：20 组随机游走，逐对计算所有峰值-谷值组合，
  与手写环回实现比对到 `1e-9`
- **边界**：空序列、单点序列、前一日为 0 都不崩

### 4.2 独立实现交叉验证（真实数据）

`scripts/verify_indicators.py` 用 **pandas 的 `cummax` / `pct_change`** 重算一遍，
和我们的手写环回实现比对（两套算法思路不同，能互相抓错）：

```
[3] 独立实现交叉验证：pandas 重算 vs 我们的实现
    ✓ 交易日数      ours=725                     ref=725
    ✓ 累计收益      ours=-0.1021441012           ref=-0.1021441012
    ✓ 年化收益      ours=-0.03680812934          ref=-0.03680812934
    ✓ 年化波动率     ours=0.2323617543            ref=0.2323617543
    ✓ 最大回撤      ours=-0.2820973928           ref=-0.2820973928
    -> 全部通过 ✅
```

五项全部对齐到 `1e-9`。

### 4.3 复权恒等式（数据口径验证）

`scripts/verify_indicators.py --check-adjust` 会再验一次：
非除权日「qfq 收益」必须等于「raw 收益」。

结论（已由探针 `06_adjust_correctness.py` 用 674 个交易日证明）：
baostock 偏差 **0.00000000**，全部一致。

## 六、数据源降级与缓存

### 缓存是必需品，不是优化

实测发现 **baostock 单次 3 年查询从 3 秒恶化到 57 秒，甚至直接挂起无返回**
（它没有超时保护）。东财同时也在限频。没有缓存，整个分析链路不可用。

- 缓存位置：`data/cache/market/<source>_<code>_<adjust>_<start>_<end>.csv`
- 有效期：默认 12 小时，`MARKET_CACHE_TTL` 环境变量可覆盖
- 命中后 725 行的读取耗时 **0.0 秒**
- 缓存失败不影响主流程（静默跳过）

### 降级顺序

```
baostock（口径完美，带 PE/PB）
  -> sina（口径正确，仅有 6.95e-06 舍入噪声，但不带 PE/PB）
  -> eastmoney（字段最全，但 qfq 口径有误，**不能用来算收益率**）
```

`series.source` 记录实际用的源，**调用方据此判断这条序列能不能算波动率**。

实测（2026-10-28 下午）：东财 `ConnectionError`、baostock 返回 0 行时，
新浪仍能以 2.4s 取到 3 年 923 行，指标链路照常跑通——这就是第三源存在的意义。

选源方式：

```bash
python scripts/verify_indicators.py --source sina    # 强制优先新浪
```

代码里 `analysis.analyze(..., source="sina")` 一路透传到底。

## 七、已知限制

| 限制 | 影响 | 后续 |
|---|---|---|
| 夏普默认 $r_f = 0$ | 数值偏高但可比 | 可接国债收益率（`bond_zh_us_rate`） |
| 未做停牌/缺失的前向填充 | 停牌当日直接跳过，交易日计数会少 | 需要精确「N 个自然日」口径时再补 |
| 单标的估值分位用自身区间 | 区间选得不同，分位会变 | 可改为固定 5 年窗口 |
| 未支持分钟级 | 只有日频 | 盘中监控需要时再加 |
