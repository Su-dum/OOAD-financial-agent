# 前端使用说明（A 股金融分析与监控智能体）

> 面向**使用者**：第一次打开界面该点什么、每个面板能看到什么、常见问题怎么排查。
> 想了解实现细节请看 [`architecture.md`](architecture.md)；想核对需求完成度请看 [`../HANDOFF.md`](../HANDOFF.md)。
>
> 界面语言：中文 · 数据范围：A 股 · 默认标的：600519 贵州茅台

---

## 一、启动

前后端要分别启动（两个终端）：

```bash
# 终端 1：后端（数据、计算、LLM 都在这一侧）
pip install -r requirements.txt
python scripts/run_api.py            # http://127.0.0.1:8000
# 接口文档：http://127.0.0.1:8000/docs

# 终端 2：前端
cd frontend
pnpm install                         # 首次
pnpm dev                             # http://127.0.0.1:5173
```

打开 <http://127.0.0.1:5173/>。

常用入口：

| 用法 | 说明 |
|---|---|
| `http://127.0.0.1:5173/` | 默认打开 600519 贵州茅台 |
| `http://127.0.0.1:5173/?code=000001` | 直接打开指定标的（便于分享链接/演示） |

> LLM 走学校内网网关（仅校园网可达）。连不上时前端会显示「LLM 降级」，
> 答案退回模板，**功能不受影响**。

## 二、页面结构

从上到下共 10 个区块 + 报告：

```
① 更新数据条       一键刷新（新闻/公告/财务/行业/事件/自动调查/清理）
② 自选股事件       增删自选、看已落库事件、点「调查」
③ 个股分析         搜索标的、切区间、指标（含财务）、走势图
   跨期对比         当前标的在不同时间段的表现（A3 跨期，窗口可自定义）
④ 预警条件         三级配置（默认/全局/个股）+ 参数边界校验
⑤ 检测到的事件     行情类 + 公告类事件清单
   横向对比         同一区间的多标的指标对比（A3 跨公司）
⑥ 分析任务         保存「标的+区间+对比组」，一键重跑
⑦ 行业监控         31 个申万一级行业指数 + 行业事件
⑧ 跨资产对比       相对表现 / 相关性 / 相对沪深300
⑨ 情景分析         改假设（冲击/波动/相关性/回撤）看组合影响
⑩ 追问             自然语言提问 + 交互式改条件
   调查报告         点「调查」或点右上角提醒后出现（事实/推测分栏 + 证据编号）

右上角浮层（不属于滚动流）：重大事件提醒
```

## 二·五、右上角重大事件提醒

刷新或定时巡检发现 **high 等级事件**后，界面**右上角**会弹出一张卡片（最多同时 3 张）：

```
┌─────────────────────────────────────────────┐
│ HIGH  宁德时代  下跌异动        2026-11-25  ×│
│ 单日下跌 -8.33%，超过阈值 -5.00%              │
│ │ 现有证据不足以确证成因：给定证据中没有… [1][2][4]│
│ AI 已分析 · deepseek-flash · 置信度 32% · 点击查看│
│ ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔  ← 12 秒倒计时  │
└─────────────────────────────────────────────┘
```

| 行为 | 说明 |
|---|---|
| **出现在哪** | `position: fixed`，右上角 16px，`z-index: 90`，不占页面布局 |
| **说什么** | 等级 + 标的 + 事件类型 + 日期 + 一行事实（`detail`）+ **一行 LLM 结论摘要** |
| **点它会怎样** | 有现成 AI 分析 → 直接打开那份报告；还没分析 → **现场用 LLM 跑一次**再打开。页面自动滚到报告处 |
| **不点会怎样** | **12 秒后自动消失**（底部进度条可见）；鼠标悬停**暂停计时**；也可点右上角 `×` 立刻关掉 |
| **会不会重复弹** | 不会。前端把「上次看到提醒的时间」存在 localStorage，后端只返回此后**新检测到**的事件 |
| **为什么不是按事件日期** | 一次刷新会把 180 天内的老事件全部重检；按事件日期过滤会让用户一开页面就被历史事件糊满 |

> 提醒与「报告」是同一套数据的两个面：提醒只说「发生了什么」，点开才看「为什么、影响是什么」。
> 后端已自动生成的高等级报告也会在这里被翻出来，不会出现「AI 分析好了但没人知道」。

## 三、① 更新数据条

点 **「更新数据」**，一次完成：

1. 新闻增量（东财列表 + 东财快讯 + 财联社电报）
2. 自选股公告增量（东财，近 400 天）
3. 自选股财务快照（按 7 天 TTL，未过期不重复请求）
4. 自选股事件检测（行情类 + 公告类）并落库
5. 已监控行业的指数检测（行业事件）
6. 对 **high** 等级、且没调查过的事件**自动生成报告**（每次最多 2 份）
7. 按保留策略裁剪旧数据（新闻 90 天 / 事件 180 天）

完成后按钮右侧显示一行汇总，例如：

```
新闻 60 · 公告 0 · 财务 5 · 自选股 6 · 事件 79 · 行业事件 19 · 自动报告 2 · 清理 0 · 耗时 19.9s
```

| 字段 | 含义 |
|---|---|
| 新闻 / 公告 / 财务 | 本次新增的新闻条数、公告条数、更新成功的财务快照只数 |
| 自选股 / 事件 | 扫描的自选股数量、检测到的事件数（含公告类） |
| 行业事件 | 已监控行业的指数事件数 |
| 自动报告 | 本次自动生成的调查报告份数 |
| 清理 | 按保留策略删除的旧数据行数 |
| 耗时 | 整个刷新的墙钟时间 |

> 刷新是同步请求，通常 15~40 秒；网络差或公告多时会久一点，但每步都有上限。

### 自动巡检（不用点按钮）

更新条左侧还有一行 **自动巡检状态** 和一个 **「立即巡检」** 按钮：

```
● 自动巡检 每 30 分钟（09:00–15:00）+ 完整档 16:00 / 21:00（仅工作日）
  · 下次 16:00 · 上次 15:30 light 0.3s · 事件 91（公告 63） · 自动报告 1
```

| 显示 | 含义 |
|---|---|
| 每 N 分钟（窗口） | **轻量档**：只检测行情 + 行业事件，**不采新闻/公告**。实测 0.1~1.8s |
| 完整档 16:00 / 21:00 | **完整档**：等同于点「更新数据」，实测约 19s |
| 下次 | 下一次自动触发时间 |
| 上次 … | 上一次巡检的档位、耗时、检测到的事件数、自动生成的报告数 |

- 绿点 = 巡检开启；灰点 = 已关闭（`MONITOR_ENABLED=false`）。
- **「立即巡检」** 不等排班，立刻跑一次轻量档——演示时想看「自动监控」效果又不想等，点它。
- 巡检跑在**后端进程**里，所以**关掉浏览器也照样跑**。

## 四、② 自选股事件

**看事件**：每条事件显示日期、股票、事件类型、严重度、详情；公告类事件带「公告」标签与「公告原文」链接。

**调查**：点右侧「调查」→ 页面底部生成报告（见第九节）。

**增删自选股**：

- 输入 6 位代码 → 点「加入自选」
- 点 chips 里的股票名 → 切到该股分析
- 点 chips 右侧「×」→ 移出自选

**列表折叠**：默认显示最新 8 条，点「显示全部 N 条」展开。

> 事件来自本地库，只有点过「更新数据」之后才会有新内容。

## 五、③ 个股分析

### 搜索与区间

- 输入 6 位代码 → 点「分析」（或回车）
- 区间：**1个月 / 3个月 / 6个月 / 1年 / 2年**，默认 1 年
- 标题右侧显示实际区间（如 `2025-11-24 ~ 2026-11-24`）

### 指标卡

| 分组 | 字段 |
|---|---|
| 收益 | 区间、累计收益、年化波动、最大回撤、回撤区间、胜率 |
| 风险调整 | 夏普 / 索提诺 |
| 估值 | PE(TTM) / 分位、PB / 分位 |
| 盈利与成长 | ROE / 净利润增速、毛利率 / 净利率、资产负债率 / EPS、每股净资产 BPS、营收增速 |
| 财务口径 | 标题旁徽标 `财务 2026-09-30 · sina_financial`；底部「数据口径：baostock / qfq / 242 个交易日」 |

**「更新财务」按钮**：强制从新浪财务接口重新抓最近一期定期报告，成功后自动重算指标。
（平时不用点——「更新数据」会按 7 天 TTL 自动维护。）

> 单位约定：收益/波动/回撤是小数（`+3.18%`），财务指标是百分数（`ROE 23.77` 表示 23.77%）。
>
> **空值带「?」角标**：指标为「—」时右侧会出现一个圆形 `?`，鼠标悬浮可看原因。两个常见情况——
> ① `PE(TTM)` / `PB` 及其分位只有 **baostock** 源提供，行情链降级到新浪/东财时为空（冷却 300 秒后自动重试 baostock）；
> ② 金融业（银行 / 非银金融）没有「销售毛利率 / 销售净利率」的商贸口径，数据源整列不披露，
> 直接显示「**不适用（金融业）**」而不是「—」。

### 走势图

- 蓝色折线 = 收盘价；底部灰色柱 = 成交量
- **橙色/红色圆点 = 事件**（按严重度着色），鼠标悬停显示日期、类型、详情
- 图下方标注区间、最低/最高价与事件个数

## 六、④ 预警条件

四类规则，每张卡片右上角标注**生效来源**：`出厂默认` / `全局配置` / `个股覆盖`。

| 规则 | 参数 | 说明 |
|---|---|---|
| 单日涨跌幅阈值 | 跌幅(%)、涨幅(%) | 默认 −5 / +5；改 `3` 表示 3% |
| 成交量放大倍数 | 窗口(天)、倍数 | 默认 20 天 / 2.5 倍 |
| 收益率统计异常 z 值 | 窗口(天)、z 值 | 默认 60 天 / 3 个标准差（D1 自动异常检测） |
| 公告事件最小级别 | low / medium / high | 控制哪些公告类事件会被生成 |

操作：

- **保存** → 写入该股票的覆盖值；保存后事件列表会自动按新阈值重算
- **恢复默认** → 删除覆盖值，退回出厂/全局配置
- 参数越界会直接报错（例如跌幅填正数、z 值填 0.5），**不会静默生效**

> 百分比在界面上填 `3`，后端存 `0.03`；只有一套口径，不用换算。

## 七、⑤ 检测到的事件

标题显示总数与构成（`行情类 7 · 公告类 22`）。每条事件：

- 日期 + 中文事件名（下跌异动 / 放量异动 / 统计异常 / 财报披露 / 分红派息 / 股份回购 / 股东增持 / 股东减持 / 重大交易 / 异动澄清 / 监管事项）
- 严重度徽标（low / medium / high）
- 详情（触发值、阈值、同日同类公告条数等）
- 公告类事件带「公告原文」外链
- 「调查」按钮 → 生成报告

**默认折叠**：只显示最近 **5** 条（列表已按事件日倒序），底部按钮「显示全部 29 条（还有 24 条）」展开。
实测 29 个事件的区间，折叠后区块高度从 **3131px 降到 630px**——否则下面几块（分析任务 / 行业 / 跨资产 / 情景）会被挤得很远。
换标的或换区间后自动收回折叠态。行业监控里的「行业事件」用的是同一个组件，行为一致（条数 ≤ 5 时不显示按钮）。

> 事件检测用的阈值来自上一节的预警条件；公告类事件来自本地公告库（先「更新数据」）。

## 七·五、横向对比（A3 跨公司/跨资产）

同一区间内比较 2~6 只标的的**基本面 + 行情**指标，回答「谁涨得多、谁波动大、谁更便宜、谁更赚钱」。

| 列 | 说明 |
|---|---|
| 标的 / 行业 | 点击整行可把主标的切过去 |
| **交易日** | 该行**实际**用到的交易日数；鼠标悬停看真实起止日 |
| 区间收益 / 年化波动 / 最大回撤 / 夏普 | 行情类（小数口径） |
| PE(TTM) / PB | 仅 baostock 源提供，降级时显示「—」 |
| ROE / 净利增速 | 最近一期定期报告（百分数口径） |

排序按「区间收益」降序，第一名带 `最佳` 徽标。

### ⚠ 窗口不一致时会给出警告

各标的的实际交易日可能不同（停牌、上市晚）。这时表头下方会出现黄色提示条：

```
⚠ 各标的实际交易日不一致（31~242 天，区间 2025-11-27~2026-11-26 / 2026-10-15~2026-11-26）：
  收益、波动、回撤是各自在自己的窗口上算的，不能直接横比。
  要看同窗口对比请用下方「跨资产对比」（会自动对齐到共同交易日）。
```

同时短窗口的那一行会在「交易日」后面标 `短窗`。

> 这是 A3 与 D3 的分界线：**A3 各自算各自的**（可以比 PE/ROE），
> **D3 先对齐到共同交易日再算关系**（可以比 β/相关系数）。窗口不齐时想做"横比"，
> 应该用 D3；A3 这张表的正确用法是「窗口一致时比基本面与区间表现」。

## 八、⑥ 分析任务

把「标的 + 区间 + 对比组」存成任务，之后一键重跑，省去每次重选参数。

**新建**：

1. 先在「个股分析」里选好标的与区间
2. 在任务面板填任务名（留空则默认 `<代码> 分析`）
3. 可选填对比标的（逗号分隔，最多 5 个，自动去掉自身与重复）
4. 点「保存当前配置（600519 · 365 天）」

**运行**：点任务行的「运行」，结果包含四块：

| 结果块 | 内容 |
|---|---|
| 指标 | 收益 / 年化波动 / 最大回撤 / 夏普 / 事件数 / ROE |
| 跨期 | 近 1/3/6/12 月（不超过任务区间）的**实际区间 / 交易日 / 累计收益 / 年化收益 / 年化波动 / 最大回撤 / 夏普 / 胜率** |
| 跨资产 | 有对比标的时：收益 / β / 与基准相关 |
| 最近事件 | 最近 3 条事件的日期与类型 |

**载入**：把该任务的标的与区间应用回主视图（等价于手动切股票 + 切区间）。
**删除**：移除任务（不影响已有结果）。

> 任务结果里的「跨期」表是从任务区间派生的固定档位（近 1/3/6/12 月）。
> 想按任意区间对比，用下面第 **七·六** 节的独立面板「跨期对比」。

## 七·六、跨期对比（A3 同一标的、不同时间段）

独立面板，位于**个股分析（含走势图）与预警条件之间**。

**为什么放在这里**：它跟上面的「个股分析」是**同一只票**，只是换个时间段看，
紧接其后才连贯；而「预警条件 → 检测到事件」是一对（设阈值 → 看触发结果），
保持相邻不被打断。

**为什么独立成面板**（而不是塞进「分析任务」）：它跟「保存的分析任务」没有依赖关系——
就是对**当前标的**做跨期比较。塞进任务面板会让人以为"要先建任务才能用"。

**头部徽标**：`A3 · 同一标的、不同时间段` + `000001 平安银行`（当前标的）。

**两种用法**

| 输入 | 结果 |
|---|---|
| 留空直接点「计算」 | **默认五档**：近 1 / 3 / 6 / 12 / 24 个月（都以今天为终点） |
| 手填窗口 | **自定义窗口**，如 `上半年:2026-01-01:2026-06-30;下半年:2026-07-01:2026-11-26` |

- 格式 `名称:开始:结束`，多段用 `;` 分隔
- 表格列：区间 / **实际区间** / 交易日 / 累计收益 / 年化收益 / 年化波动 / 最大回撤 / 夏普 / 胜率
- 结果标题会写清「**哪只票 + 哪套窗口**」，例如
  `区间指标 · 000001 平安银行 · 默认五档`
  或 `区间指标 · 600519 贵州茅台 · 自定义窗口 · 上半年:…;下半年:…`

**两个防误读设计**

1. **切换标的后表格自动清空**（而不是留着上一只票的数字）——空态会写明"点「计算」查看
   `000001 平安银行` 在默认五档…的表现"。
2. **「实际区间」列**：请求 `2026-01-01` 起，实际首日可能是 `01-05`（节假日）；
   区间也可能因停牌/上市晚而短于请求值。**每行按自己的窗口计算，不同长度区间的年化值不可直接横比。**

> 为什么要「自定义」：任务的跨期档位是从「天数」自动派生的（如 90 天 → 近 1 个月 + 近 3 个月），
> 只能覆盖"以今天为终点"的窗口。想看「上半年 vs 下半年」这种**非今天终点**的对比，就得手填。

## 九、⑦ 行业监控

监控对象是**申万一级行业指数**（31 个），不是成分股聚合。

- 已监控行业显示为 chips：点名字看走势，点「×」移出监控
- 下拉选行业 → 「加入监控」（首次启动默认监控银行 / 食品饮料 / 电子）
- 「刷新行业事件」→ 对已监控行业重新检测并落库
- 选中行业后显示：成分股数、PE(TTM)、PB，以及**行业指数走势图**（事件点同样画在曲线上）
- 「行业事件」列表与个股事件同一套规则，但**没有「调查」按钮**（行业事件的调查是下一步工作）

> 行业事件与个股事件共用事件表，用 `scope=industry` 区分；刷新时也会自动检测已监控行业。

## 十、⑧ 跨资产对比

- 输入框填 2 个以上代码（逗号分隔，默认 `600519,000001,300750`）→ 点「对比」
- 基准固定为沪深300（`sh000300`）

结果三块：

1. **相对表现**：各标的净值曲线（首日 = 100）+ 沪深300 虚线
2. **区间指标表**：行业、区间收益、年化波动、最大回撤、夏普、β、与基准相关、超额收益
3. **相关性矩阵**：日收益率皮尔逊相关系数热力表（蓝正红负，越深越强）

> 只用**共同交易日**计算；共同交易日不足 80% 时基准会被丢弃（避免 β 失真）。

## 十一、⑨ 情景分析

「如果我改一个假设，组合会怎样？」——五个滑杆，改完点「重算」：

| 控件 | 默认 | 含义 |
|---|---|---|
| 市场冲击（一次性） | −10% | 沪深300 一次性涨跌，按 β 传导到每只标的 |
| 波动率倍数 | ×1.5 | 放大/缩小所有标的波动率（恐慌 / 平静） |
| 相关性压力 | 0.60 | 0→保持原样，1→所有资产完全同涨同跌（危机） |
| 持有期 | 20 天 | 用于持有期 VaR 与历史最差窗口 |
| 施加直接回撤 | 勾选，−15% | 与冲击**复利叠加**成「情景合计影响」，并给出「回本需涨幅」 |

结果：

- **卡片**：市场冲击传导（组合 β × 冲击）、年化波动（基线 → 压力）、
  1 日 VaR 95%/99%、持有期 VaR、情景合计影响、回本需涨幅
- **逐标的贡献表**：权重、β、单标的冲击、对组合贡献、压力后波动
- **历史最差窗口**：最近区间内最差的 20 个交易日（买入持有口径），
  给出窗口起止、组合收益与各标的收益
- 底部注释：参数法假设、投资建议免责

> 情景分析默认走新浪快源（不碰 baostock），一般 5~10 秒出结果。
> 单标的也能看，但面板按组合口径设计（≥2 只标的，等权）。

## 十六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面白屏 / 接口 404 | 后端没起或端口不对：确认 `python scripts/run_api.py` 在 8000，前端 `vite.config.ts` 代理到 8000 |
| 「加载中…」很久 | 首次拉行情要走外部源（baostock 可能慢），之后走 CSV 缓存 |
| 没有事件 | 先点「更新数据」；或阈值太严（预警条件里放宽后再看） |
| 公告/财务是空的 | 该标的还没刷新过：点「更新数据」，或个股面板的「更新财务」 |
| 追问显示「LLM 降级」 | 网关 503/超时（仅校园网可达），答案已退回模板；看 `llm_meta.reason` |
| 行业指数加载失败 | 申万指数接口偶发限流；稍后点「刷新行业事件」重试 |
| 情景分析很慢 / 失败 | 需要 2 只以上标的的共同交易日；默认走新浪源，若外部源不稳可稍后重试 |
| 端口 5173/8000 被占用 | 换端口启动，并同步改 `frontend/vite.config.ts` 的 proxy target |
| 改了阈值但事件没变 | 保存后会自动重算；若没重算，切一次区间或点该股「分析」 |

cd frontend && npx tsc --noEmit      # 前端类型检查

## 十八、别搞混：界面上有两处「事件」

这两块**不是同一份数据**，容易看混：

| | ① 自选股事件（页面最上方） | ② 检测到 N 个事件（个股分析下方） |
|---|---|---|
| **范围** | **所有自选股**（当前 7 只） | **只有当前分析的这一只** |
| **数据来源** | `GET /api/events/watchlist` → 读 `event` 表（**已落库**） | `GET /api/stocks/{code}/events?start=&end=` → **现场重算** |
| **时间范围** | 不跟随区间，取最近 50 条 | **严格按当前区间**（跟随区间按钮/日期选择器） |
| **什么时候更新** | 只在「更新数据」/ 自动巡检后（落库那一刻） | 每次切标的、切区间、改预警阈值都**立即重算** |
| **用的阈值** | 落库时那次巡检用的阈值 | **当前**的预警阈值（改完立刻反映） |
| **有没有「公告原文」链接** | 没有（列表较窄，只显示 detail） | **有**（`source_url` 可点） |
| **典型用途** | 一眼扫「我的自选股最近发生了什么事」 | 深看「这只票在这段时间里发生了什么」 |

一句话：**上面是「我的组合里谁出事了」，下面是「我正在看的这只票在这段时间出没出事」。**

> 另外还有两处事件列表，是**行业维度**的：行业监控面板里的「行业事件（N）」（`scope=industry`），
> 以及分析任务结果底部的「最近事件」（任务标的那只票）。后者与 ② 同源，只是限定在任务区间。
